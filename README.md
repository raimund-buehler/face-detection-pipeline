# face-gaze-pipeline

Processing and analysis pipeline for a video-based eye-tracking study: detecting faces
in recorded video, mapping gaze samples onto them, and analysing the resulting
fixation measures.

The code covers the full path from raw recordings to the figures and model tables that
appear in the manuscript.

## What's here

```
detection/    Python — face detection (MTCNN) on video frames, gaze-to-face mapping
analysis/     R — preprocessing, dataset assembly, models, figures, tables
outputs/      Figures and model output tables produced by the analysis
config/       Templates for machine-specific paths (the real ones are not committed)
```

### `detection/`

| Script | Purpose |
|---|---|
| `make_frame.py` | Extract frames from the session recordings |
| `FastMTCNN_new.py` | Batch face detection with MTCNN |
| `filter_conf.py` | Filter detections by confidence |
| `gaze_for_frame.py` | Map gaze samples onto detected face regions |
| `draw.py` | Overlay detections and gaze for visual checking |

### `analysis/`

Numbered so the order of execution is explicit:

| Stage | Contents |
|---|---|
| `00_preprocessing/` | Session-level eye-tracking features, sliding-window timecourses |
| `01_dataset_assembly/` | Merge eye-tracking, questionnaire and cortisol data |
| `02_main_manuscript/` | Models reported in the main text |
| `03_supplementary/` | Supplementary analyses |
| `04_figures/` | Figure scripts |
| `05_tables/` | Summary and model tables |

### `outputs/`

Figures (PNG, PDF, SVG) and model output tables. These are **aggregate results only** —
model terms, contrasts, test statistics. No individual-level rows.

## Data availability

**Individual-level data are not included in this repository and are not publicly
shared.** The dataset contains health-related information — clinical questionnaire
scores and pharmacological condition — that participants did not consent to have
released publicly.

The analysis code is therefore not runnable end-to-end from this repository alone. It is
published so the processing and analysis decisions can be read and checked, not so the
results can be regenerated by anyone.

Data are available from the author on reasonable request, subject to the terms of the
study's ethics approval.

## Running it with the data

If you do have the dataset:

```bash
cp config/paths.example.R config/paths.R      # set recordings_root
cp config/paths.example.py config/paths.py    # set FRAME_OUTPUT_DIR
```

Both files are gitignored. The R scripts read paths through `here()` relative to the
project root; run them in the numbered order above.

Python dependencies are in `detection/requirements.txt`. The R analysis uses
`tidyverse`, `here`, `lme4`/`lmerTest`, `emmeans` and `ggplot2`.
